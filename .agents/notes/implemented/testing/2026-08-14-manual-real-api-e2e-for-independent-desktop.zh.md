# Agent Note: 独立 Desktop 仓库的手动真实 API e2e

Status: implemented

[English](2026-08-14-manual-real-api-e2e-for-independent-desktop.md) | 中文

## 问题

无密钥测试能够证明组装后的行为，但不能证明真实提供方请求。真实 API 套件在没有密钥时会自行跳过，因此自动工作流若没有明确的密钥检查，可能在未执行提供方调用时报告绿色。

独立私有 Desktop 仓库当前没有配置真实提供方的仓库 secret。临时本地测试密钥不得成为仓库 secret，也不得为了让 CI 看似完整而上传。

## 决策

[e2e.yml](../../../../.github/workflows/e2e.yml) 只由 `workflow_dispatch` 触发。它保持与无密钥 [CI](../../../../.github/workflows/ci.yml) 分离，因此普通拉取请求、推送和定时自动化既不会获得真实提供方凭据，也不会依赖它。

该工作流仅在 preflight 和真实 e2e 测试步骤中将 `DEEPSEEK_API_KEY_EXTERNAL` 仓库 secret 映射为 `DEEPSEEK_API_KEY`。检出、pnpm 设置、依赖安装和构建都不带这个环境变量执行。

当 secret 缺失或为空时，preflight 会明确失败。它会在 `pnpm run test:e2e` 有机会自行跳过之前指出配置错误，避免手动调用变成假阳性绿色结果。本决策不配置仓库 secret，也不上传任何本地临时密钥。

## 曾考虑的替代方案

- **在拉取请求、推送或定时任务中运行真实提供方 e2e** — 当前否决：这会让外部凭据成为自动 CI 的一部分，需要另一项专门决定其触发条件和威胁模型。
- **把临时本地密钥配置为仓库 secret** — 否决：本地测试的授权不等于持久保存仓库凭据的授权。
- **允许缺失 secret 时自行跳过** — 否决：被跳过的套件无法证明真实提供方路径曾被执行。
- **把凭据放进主 CI 工作流** — 否决：主聚合流程保持无密钥，并可在没有 secret 访问权限时复现。

## 后果

需要真实提供方证据的维护者会显式启动该工作流，并必须通过仓库的 secret 管理控制确认已配置所需 secret。缺失 secret 是有用的配置失败结果，而不是通过的测试结果。

未来若要自动运行真实 API 门禁，必须另行明确决定其事件、凭据暴露、分支保护角色和运营归属。在此之前，自动 CI 拓扑保持无密钥。
