# Agent Note: 不使用 Pages 的私有文档验证

Status: implemented

[English](2026-08-14-private-documentation-verification-without-pages.md) | 中文

## 问题

私有自动化仓库需要在每项受选中的变更上运行生产文档构建，但 GitHub Pages 可能把生成内容暴露到仓库外部。即使仓库变量能够限制部署，自动化工作流仍会保留持久的发布能力和提升后的 Pages 权限。

## 决定

文档工作流只包含无条件执行的 `verify` 作业。它使用冻结的依赖安装，设置 `DOCS_BASE=/`，并在受选中的 `master` 变更和手动触发时运行 `pnpm run doc-sync`。该工作流及其唯一作业只具有仓库读取权限。

该工作流没有 Pages 配置 action、产物上传、部署 action、Pages 权限、OIDC 权限、发布变量或 Pages 专用并发组。它不能启用 Pages、选择可见性或发布文档。网站投影仍按[权威文档投影](2026-07-13-documentation-site-projection.md)所述得到验证。

## 考虑过的替代方案

**保留由变量限制的 Pages 发布作业。** 变量可以阻止常规运行进入该作业，但检入的工作流仍会保留外部发布能力以及使用它所需的权限。

**从工作流启用 Pages。** 自动启用需要单独授权的高权限凭据，并会让托管状态成为 CI 副作用。

**跳过生产文档构建。** 移除部署路径不能把 VitePress 或链接错误推迟到无关的未来发布决定。验证作业会保留既有的质量信号。

## 后果

受选中的文档变更总会获得冻结的生产构建，且不能改变 GitHub Pages 状态或暴露生成的站点。仓库管理员仍完全控制该工作流之外的任何未来发布决定。

未来的 Pages 或其他托管集成需要用户明确授权、独立的实现决定，以及对目标位置和可见性策略的聚焦验证。设置仓库变量无法将它重新引入。
